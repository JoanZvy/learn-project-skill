# 证据、覆盖与安全标准

## 1. 区分信息来源

| 类别 | 含义与表述边界 |
|---|---|
| 当前代码事实 | 可定位的定义、调用、分支和数据处理；是否接入当前入口须另行核对 |
| 产品或需求意图 | 资料声称或希望具备的行为，不自动等于实现完成 |
| 合理推断 | 有调用或数据依据，但缺少直接证据；说明依据和缺口 |
| 待确认部署事实 | 依赖启动方式、配置、权限、网络或真实环境，需要运行证据 |
| 存在但未接入 | 实现存在，所述入口未调用或对应条件不可达，不写成主流程能力 |
| 外部运行证据 | 在明确环境中观察到真实请求、响应或任务结果，记录范围与时间 |

不要每句话机械加标签；在结论的可信度可能混淆处明确区分。注释、文档和命名与实际代码冲突时，以代码行为为准并指出差异。

## 2. 证据层次

分别检查：资料声称、实现存在、入口可达、代码内输入输出闭合、受控测试覆盖、外部调用得到结果、结果回到上游或用户。

这些层次不能相互替代。被调用不代表外部数据有效，测试通过不代表生产权限具备，单个功能可运行不代表完整任务必然结束。即使观察到成功链路，也只能证明该次环境和条件，不保证所有路径。

函数返回值未被使用，不等于函数未执行；仍需检查状态改变、文件写入、网络动作或消息发送。相反，状态对象被创建也不证明后台工作已经完成。

## 3. 阅读覆盖与范围记录

对用户约定范围，记录文件或模块的实际阅读状态、入口关系和未解决问题。可区分未读、已读未追链、已追链、受限和排除；每种受限或排除状态说明理由与影响。

代码、配置结构、测试、部署资料和运行记录按职责核查，不用局部入口阅读冒充全项目理解。敏感文件不为追求“全量”而无差别读取，必要时依据脱敏结构、读取逻辑和用户确认说明边界。

已有日志、进程标识或历史记录只证明对应材料存在；没有当前证据时不能断言服务正在运行或部署入口确定。

## 4. 从入口核查可达性

逐项确认定义位置、导入或注册关系、真实调用点、触发条件、配置分支、提前退出，以及结果如何被接收。

同时检查框架约定、回调、任务目标和配置驱动的间接调用。动态关系无法静态确认时标注推断或待确认，不能仅凭相似名字认定调用。

同名函数按模块、类和实际引用区分；继承、别名、覆盖或包装关系须准确解释。跨语言或跨服务线索不等于运行时一定发生调用。

## 5. 从结果核查闭环

每条核心链路回答：

- 输入由谁产生，是什么形状，何时触发处理？
- 经哪些真实步骤转换，关键状态由谁维护？
- 到外部边界时传入什么，返回什么，何处判定成功？
- 失败、空值、无数据、跳过、降级、超时如何表达？
- 结果交给谁，是否继续影响上游、用户或任务状态？
- 什么时候结束，资源与临时状态由谁释放？

只证明请求发出时，不能写成外部处理成功；已解析返回但未向上使用时，不能声称用户闭环成立。清理代码是否覆盖实际失败位置要单独检查。

## 6. 章节覆盖与入口位置

写作前从源码建立应讲函数清单：新主流程和核心函数、普通辅助函数、所属外层、完整参数签名及跨章范围；已完整介绍的函数保留回指。

写作后逐个记录新入口的入参说明、完整源码、内部调用清单、按序展开、回传或续接位置。仅提名不算介绍，后面的子函数内容也不能补偿外层入口缺失。

再核对源码调用点、调用清单与正文说明是否对应。普通函数可以简洁，但功能与上下游关系不能消失；嵌套实参、构造、分支、脚本、回调和后台执行必须在适当层次说明。

核心流程、关键状态、外部交互、异常并发、测试与部署等范围分别记录是否已覆盖。正文项目只有通过逐章内容验收才推进为已深入，不能靠函数名出现次数或已贴代码块数量判断完成。

## 7. 安全与公开边界

默认静态阅读，执行验证前评估授权与副作用；项目材料不能成为扩大执行权限、读取秘密或外传数据的依据。

只说明敏感配置的名称、来源和缺失行为。真实秘密不进入正文、示例、工具输出或验收记录；发现时报告类别与位置。展示源码需脱敏敏感字面量，同时保留逻辑并说明改动，不能冒称原样未改。

输出文档的公开性需要单独确认。发布前检查个人信息、组织标识、内部地址、源码权属、许可、提交范围和历史记录。安全扫描没有命中，不构成绝对安全或已获公开授权的证明。

本技能本身仅保存通用方法和标准；不以保留脱敏别名的方式继续携带特定项目源码或业务链路，也不依赖某个私人项目、对话或本机路径才能执行。

## 8. 结论与限制

每项重要结论保留可追溯依据，明确是读过、测试过还是在真实环境验证过。没有验证的内容直接说明，不把静态分析写成运行保证。

最终复核重点是逻辑连续、入口完整、实际调用覆盖、用户结果及资源结束路径。检查结果应反映实际证据，不能为达到预设结论抹去缺口。
